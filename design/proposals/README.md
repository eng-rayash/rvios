# RVIOS — المقترحات البصرية

ثلاثة اتجاهات بصرية كاملة، كل واحد ملف HTML مستقل بصفر تبعيات بناء.

## التشغيل

```bash
cd F:\rvios\design\proposals && python -m http.server 4321
```

ثم افتح **http://localhost:4321/compare.html** — يعرض الثلاثة جنباً إلى جنب مع
مبدّل لوحة/عرض/وضع. أو افتح أي مقترح مباشرة:

| المقترح | الرابط |
|---|---|
| A — أرشيف ملكي | `a-heritage/index.html` |
| B — استوديو حديث | `b-studio/index.html` |
| C — معرض داكن | `c-gallery/index.html` |

(تعمل أيضاً بفتح الملف مباشرة عبر `file://` — الخطوط منسوخة محلياً.)

## لماذا HTML ثابت وليس صفحة داخل الموقع

وقت بناء المقترحات كان الموقع معطوباً: خط النص الأساسي ساقط (`--font-panorama:
"Hacen"` لا يطابق أي `@font-face`، والعائلة المعلَنة اسمها `"Generator"`)، وNext 16
يعمل مع React 18. أي مقترح داخل الموقع كان سيرث تلك الأعطال ويُفسد الحكم.
خطأ الخط أُصلح منذ ذلك الحين؛ ترقية React ما زالت قائمة.

## البنية

```
_shared/
  fonts.css     خطوط الهوية الست (نسخة محلية من rvios-site/public/fonts)
  fonts/        ملفات الخطوط
  base.css      هيكل بلا أي قيمة بصرية — كل لون وحجم يأتي من :root
  preview.js    لوحة التوكنز + فحص الاكتمال
compare.html    مقارنة جنباً إلى جنب
```

## القاعدة الحاكمة: ما تختاره كتلة توكنز لا «شكل»

كل مقترح يبدأ بكتلة `:root` **بأسماء التوكنز النهائية نفسها** التي ستصدّرها
`packages/design-tokens`. الاختيار يُترجَم مباشرةً بلا إعادة تفسير:

```
--color-primary-{50,100,300,500,700,900}   --color-gold-{100,500,700}
--color-ink-{900,700,500,300}              --color-surface-{0,1,2,3}
--color-border-{subtle,default,strong}     --color-{success,warning,danger,info}
--color-text-{primary,secondary,inverse,on-primary}
--radius-{xs,sm,md,lg,xl,full}             --space-{1..24}  (سلّم 4px)
--shadow-{xs,sm,md,lg,glow}                --font-{display,body,mono}
--text-{xs..5xl}                           --leading-{tight,normal,loose}
--motion-{fast,base,slow}                  --ease-{out,in-out,spring}
--z-{base,dropdown,sticky,overlay,modal,toast}
```

`preview.js` يفحص الاكتمال عند كل تحميل ويعرض النتيجة في شريط الأعلى وفي الـ
console. الثلاثة اليوم: **✔ ٧٨ توكناً مكتملة**.

كل مقترح يعرّف الوضعين الفاتح والداكن، فالوضع الداكن مصمَّم لا مُرقَّع لاحقاً.

## اللوحات في كل مقترح

1. **الصفحة الرئيسية** — hero + إحصاءات + الخدمات
2. **المعرض** — بطاقة مشروع + شبكة + رأس صفحة `/work/[slug]` بشارات ومؤشرات نتائج
3. **لوحة التحكم** — sidebar + هيدر + KPIs + جدول + شارات + حقل نموذج
   (اختبار الكثافة العالية — وهو ما تفشل فيه اللوحة الحالية)
4. **التوكنز** — عيّنات الألوان وسلّم النصوص والحواف والظلال، مقروءة من القيم الحيّة

**المقترح A وحده** فيه لوحة إضافية:

3. **عارض الأعمال (Coverflow)** — عارض ثلاثي الأبعاد تفاعلي. انقر بطاقة جانبية،
   أو استخدم الأسهم، أو اسحب باللمس. (فتُصبح لوحة التحكم ٤ والتوكنز ٥.)

   المنطق نُقل إلى مكوّن إنتاجي في
   [`rvios-site/components/CoverflowGallery.tsx`](../../rvios-site/components/CoverflowGallery.tsx)
   مع `CoverflowGallery.module.css`. يستهلك التوكنز عبر `var()` بقيم احتياطية،
   فيعمل اليوم ويلتقط `packages/design-tokens` تلقائياً عند وصولها.

   فروق عن مرجع Framer الأصلي:
   - **RTL صحيح** — السهم الأيسر يتقدّم، والبطاقة التالية تدخل من اليسار
   - أزرار حقيقية بدل `div` قابل للنقر، مع `aria-live` يعلن التغيير
   - البطاقات المخفية تخرج من ترتيب التبويب (`tabIndex={-1}`)
   - سحب باللمس + `Home`/`End`
   - `prefers-reduced-motion` يُلغي الحركة ويبقي الوظيفة
   - التقدّم التلقائي يتوقف عند التحويم والتركيز وإخفاء التبويب
   - `next/image` مع أولوية للبطاقة الفعّالة وتحميل كسول لما عداها
   - النقر على البطاقة الفعّالة يفتح المشروع (`onOpen`) بدل أن يقفز للتالية

## الاتجاهات

| | A — أرشيف ملكي | B — استوديو حديث | C — معرض داكن |
|---|---|---|---|
| الأساس | إيفوري `#FAF8ED` | أبيض `#FFFFFF` | جرافيت `#0D0E10` |
| الحواف | 0–6px (حادة) | 6–28px (سخية) | 4–20px |
| العنّابي | مساحات كبيرة، حضور طاغٍ | لكنة فقط | توهّج وحدود |
| أداة الفصل | خطوط وشعيرات ذهبية | ظلال ناعمة | حدود مضيئة |
| خط العناوين | Yapari ضخم | Generator | Yapari |
| الخدمات | صفوف تحريرية مرقّمة | بطاقات ناعمة | بطاقات بأرقام ضخمة |
| الوضع الافتراضي | فاتح | فاتح | **داكن** (الفاتح هو المعكوس) |
| النسب | وريث `rvios-owner` التحريري | وريث `RVIOS_APP/web/landing` | جديد |
| نقطة القوة | هوية متميزة لا تشبه أحداً | آمن ومصقول ومألوف للعملاء | الأقوى للمعرض؛ يوحّد الموقع مع اللوحة الداكنة أصلاً |
| نقطة الضعف | يعتمد على Yapari (ترخيص Trial) | قد يبدو عاماً | قراءة المدونة الطويلة أصعب |

**المزج مشروع:** «B للموقع + C للوحة التحكم» خيار صالح — الوضعان معرَّفان في الثلاثة.

## قرار مطلوب قبل الاعتماد: ترخيص Yapari

`YapariTrial-Bold.ttf` و`YapariTrial-ExtraBold.ttf` — «Trial» يعني ترخيصاً
تجريبياً لا يغطي الإنتاج، والملفان منشوران في مستودع عام. المقترحان A و C
يعتمدان عليه للعناوين. الخياران: شراء الترخيص، أو استبداله بخط عرض مرخّص.
المقترح B لا يستخدمه إطلاقاً.

## ملاحظات على الحالة الحالية ظهرت أثناء البناء

- **خط النص كان معطّلاً وقت بناء المقترحات** — `--font-panorama: "Hacen"` لا يطابق
  أي `@font-face` (العائلة المعلَنة اسمها `"Generator"` وتحمّل `Hacen Liner Screen.ttf`).
  أُصلح لاحقاً بكلمة واحدة. وحُذف `PanoramaNaskhMobile-Regular.otf` (172KB) لأنه لم
  يُحمَّل قط في أي تطبيق.
- التدرّجات الرمادية في بطاقات المعرض نائبة عن صور المشاريع الحقيقية — وهي
  القيم السداسية الوحيدة خارج كتل `:root` في المقترحات.
